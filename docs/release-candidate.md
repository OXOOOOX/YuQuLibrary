## 发布前核对与备份

1. 记录 `/opt/yuqu/current`、当前容器 image ID、固定 Node／PostgreSQL 镜像、生产迁移账本、私有媒体目录、容量和当前任务状态。确认候选摘要与已验证版本一致。HTTP `/api/health` 仅证明进程存活。
2. 排空唯一共享 Bridge。停止命令返回 0 不能单独证明已退出：当前控制脚本等待 30 秒后可能仍处于排空；必须检查旧 supervisor 和 Worker 均停止、没有未结任务，再切换源码。不要启动旧鱼趣独立 Bridge，与 Cat 共用的唯一实例保持项目隔离。
3. 获取鱼趣发布锁与服务器构建锁，按独立目录构建新镜像。保留旧镜像、旧源码和原外置配置，不改 Cat 服务或配置。
4. 进入维护窗口：暂停鱼趣 Web、下载／回收 Worker 和托管 ASR 写入，数据库保持运行。确认没有业务写入后，对同一时间点的数据库、媒体、外置配置、镜像版本和迁移账本建立备份并计算摘要；配置备份限制权限，禁止放入公开归档。
5. 将备份恢复到独立临时数据库及媒体目录，核对表数、记录摘要、媒体抽样哈希和私有读取。备份命令成功不等于恢复可用。恢复验证前不执行正式迁移。

## 切换顺序

1. 在已核对的鱼趣项目／新发布目录加载受限外置发布参数，使用新镜像执行迁移。通过标准输入运行远程 Bash 时，`docker compose ... run --rm -T migrate </dev/null`，防止容器消费后续脚本输入。
2. 迁移逐文件提交，并非 14 份脚本整体事务；某份失败时前面的文件可能已提交。保留完整错误、重新读取账本，修复后从该状态重试；禁止假设数据库没有变化或手工删除迁移记录。
3. 启动新鱼趣 Web 与 ingestion，验证数据库读取、私有媒体、分页、登录和旧记录；然后用新代码启动唯一 Bridge，确认旧进程已消失、选段／章节／检索／分段及整期总结能力已登记、各项目配置仍隔离。恢复托管 ASR，并确认没有第二个直接 Worker。
4. 用本轮新建的受控资料完成生产验收：新旧客户端读取边界、选段与追问、搜索、收藏、引用返回、章节真实生成／失败续接、长节目检索／无证据／原证据追问、分段及整期总结／冻结引用／停止续做与旧 Worker 隔离；最后只对该样本验证音频清理和整期删除。保留历史用户数据摘要对照，不用旧用户资料测试删除。
5. 通过真实 HTTPS 与客户端验证后才更新发布记录和 `current` 指针。切换指针本身不替换容器或数据库。保留原镜像和备份直到验收结束。

现有 `deploy/release.sh` 只支持首次部署，不能拿来执行本次升级。正式上线应根据当时实际运行目录、镜像和备份摘要构造具体命令，不能把本文当成已核对的服务器状态。

## 失败与恢复

- 新代码产生的选段／检索消息、收藏和章节涉及新契约；不能直接删列、删表或降级后继续写入。先停止相关写入与唯一 Bridge，保留现场日志及失败后的数据副本。
- 如果只回切程序，必须先证明旧版本对现有数据库和新消息类型兼容；否则从维护窗口备份同时恢复数据库与媒体，并说明恢复点之后的数据处理方式。不得用覆盖式恢复静默丢弃用户新数据。
- 旧镜像、`current`、Bridge 源码和对应外置配置需要共同核对；任何一个单独回退都不代表恢复完成。复验私有媒体、迁移账本、旧问答／收藏、任务租约和多端播放后，才解除维护状态。
