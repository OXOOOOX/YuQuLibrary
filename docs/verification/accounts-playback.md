日期：2026-11-16。范围：本地网页、HarmonyOS 7 模拟器、独立 PostgreSQL、两分钟受控音频。项目未部署，测试邮件实际收件已确认，两端真实验证码登录和真机尚未验收；主流程测试后补充的 SMTP 结果见下节。

## 后续 SMTP 配置、连接与实际收件验证

2026-11-16 21:52（北京时间），使用用户提供的网易客户端授权码，通过 `smtp.163.com:465` 的 TLS 连接和 SMTP 账号认证。凭据仅写入忽略提交的本机 `.env`，设置 `MAIL_MODE=smtp`；其他配置保持不变。验证调用 `transport.verify()`，没有发送邮件，不能据此断言实际收件或垃圾邮件分类正常。

## 实现结果

- 网页 EventSource 与鸿蒙 HTTP 流连接、游标恢复、主动轮换、UTF-8 分片解析。
- 邮箱验证码、发送限制、有效期、失败次数与单次消费；网页 Cookie、鸿蒙独立设备令牌、当前用户及退出撤销。
- PostgreSQL 持久化账号与播放快照；接管代次、设备归属、幂等请求、上报序号、按用户事件回放。
- 两端默认静音跟随；主动接管后播放，旧设备暂停。暂停、回听、倍速及时同步，网络未知结果保留原序号和内容重试。
- 鸿蒙 AssetStoreKit 保存设备令牌，重启恢复登录但不自动播放；网页标签页协调会话变化。

## 自动化与审阅

真实 PostgreSQL 集成测试覆盖 12 组行为：空库迁移与重复执行、发送限流、失败投递废弃挑战、五次错误累计、并发验证码消费、会话创建失败回滚、同用户设备与跨用户隔离、同时接管与迟到重试、乱序/重复/回听、事件原子性和回放、已有 SSE 会话撤销、Origin 与请求体边界。

最终启动复查还修复了迁移登记表的命名空间问题：角色名为 `yuqu` 时，创建同名 schema 会改变默认搜索路径；未限定表名导致第二次运行读到另一张登记表。现在始终使用 `public.yuqu_schema_migrations`，独立测试库首次迁移、第二次执行及开发库重复迁移均通过，无需重建业务数据。此前检查产生的未使用 `yuqu.yuqu_schema_migrations` 保留于本地开发库，不再被读取。

原生服务替身测试覆盖 HTTP/播放器/安全存储的异步代际、未确认上报重试、过期显示、退出清理；另有 5 组 reset 竞争场景覆盖旧 GET、report、takeover、旧 401 与 finally，不允许旧响应恢复控制权或解锁新请求。这类测试不替代系统安全存储或媒体行为，相关真实模拟器项已另列。

网页专项测试使用真实 Chrome Web Locks 和 HttpOnly 测试 Cookie，模拟 HTTP/SSE 以控制响应先后，验证跨标签页认证请求排序、恢复快照重试、reset 前的旧响应隔离。7 项专项用例通过。独立只读审查发现的排队退出会话变化也已修复：获锁后会核对退出请求原本对应的会话；测试证明会话已变化时不会发送 logout，也不会撤销新登录。

最终 `npm run check` 通过配置解析、两层类型检查、14 项测试入口与网页生产构建；其中 12 项数据库用例因该命令未加载专用测试连接而明确跳过。另行执行 `npm run test:integration` 得到 12/12 通过、零跳过。原生测试入口内部包含多个异步场景，不把文件数当作场景数。`npm run harmony:build` 构建成功，最终包安装与原生运行结果已在上表单列。
