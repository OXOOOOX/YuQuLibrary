# 转写自启动、异常恢复与资料管理验证

日期：2026-11-17。正式入口：https://fish.sdspeed.com.cn 。最终服务器版本 `20261117-2fe19abc0c3196d0`，数据库迁移到 0008。原有 3 份生产资料均保留，测试仅删除本轮新建样本。

## 本轮交付

- Windows 当前用户登录后自动启动本机转写；计划任务每分钟检查守护进程，守护进程对 Worker 做心跳检测和有上限的退避重启。主动停止会关闭自动恢复开关。
- 模型使用 SQLite 事务互斥，记录父进程与模型子进程；先登记再发送启动握手，管道断开后模型与解码进程退出。转写段提交成功后才继续下一段，旧租约不能写回。
- 新的推理临时目录带归属标记；仅回收父进程和登记子进程均已退出的目录，拒绝链接，保留未知/旧版未标记目录。
- 两端提供“清理音频”和“删除整期资料”，均先说明后果。音频清理要求整期转写完成，保留文稿与聊天，可独立阅读和继续提问；整期删除会撤销处理任务并清理关联记录。
- 默认每账号 1 GiB 音频额度，50 项导入、同时 5 项等待或下载，每项预留 100 MiB。容量面板显示已用、预留和待回收；音频清理不释放资料数量，整期删除或移除任务才释放数量。
- 文件进入持久回收队列；成功删除后才释放待回收容量。失败/过期下载保留旧文件身份，容量阻塞时短暂退避，不阻塞其他账号。已打开的慢音频流会复核授权并在失效后关闭。

## 转写实测

Windows 计划任务 `YuQuTranscription` 已安装。实际验证了 Worker 强制退出后自动重启、守护进程退出后由计划任务恢复、显式停止后触发计划任务仍保持停止。任务执行结果为 0；未注销或重启用户电脑，不宣称验证了未登录时启动。

首次真实转写暴露了 Windows CRT 管道锁问题：后台阻塞读取 stdin 时，NumPy 原生模块导入停住。隔离脚本稳定复现后改为 `PeekNamedPipe` 检查可读数据，避免持锁阻塞；实际 Python 环境的 NumPy/soundfile 导入、分段 CRLF、父进程死亡清理回归通过。44.4 秒真实公开音频隔离推理约 52.1 秒完成。

通过已登录鸿蒙模拟器导入新的公开验证副本：

`https://cdn.twit.tv/drops/hot/1/1.mp3?yuqu-recovery=20261117-stage10`

实际时长 148,968 ms，2,563,438 字节。转写任务保存前 30,000 ms 后受控强杀 Node；venv 启动器与实际 Python 进程均退出。服务自动重启、等待旧租约到期后从 30 秒续写，最终 5 个核心段全部完成。第一段内容摘要在中断前后均为 `10aa605bacd7a8ead5380ae1fdf8e934`，没有重写已保存段。首次阻塞后的停止与这次中断共占用前两次尝试，第三次完成；没有重置任务次数掩盖失败。
