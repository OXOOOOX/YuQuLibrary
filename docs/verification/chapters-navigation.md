# AI 章节导航本地验收

日期：2026-11-18。覆盖 R16／A15。章节代码、真实模型调用、网页和鸿蒙模拟器在本机独立测试环境验证；尚未部署到生产，也未在真机安装。

## 已实现的范围

- 完整文稿由用户主动发起章节生成；固定转写任务和完成水位，生成请求幂等，同一版本复用现有结果。
- 模型按主题提出标题及连续原文编号；服务端核对全部句子覆盖，时间仅取已保存片段的最小起点／最大终点。支持跨批首章续接、重叠时间和零时长文字，不伪造章节时间。
- 每批最多 600 句／24,000 字符，最多 128 批；每批最多 32 个章节。大于上限明确拒绝，批次不是固定时长章节。
- 已完成批次持久保存，后续失败可重试、可取消；旧租约和迟到结果不能覆盖。每用户最多 2 份活跃文档，聊天优先领取。
- 两端提供 40 条分页目录、起始原文定位、返回目录、显式播放和本章末尾停止。浏览不接管播放；清理音频保留章节，整期删除级联清理文档与任务。
- 零时长文字保留供阅读，无可播放时长的章节禁播。鸿蒙在目录顶部和底部提供翻页，翻页回到标题；原文视图保留固定的返回目录入口。

## 数据与验证边界

所有数据库测试只连接独立 `_test` 数据库。本轮建了独立账号与两份受控资料；媒体使用两分钟验证音频，文稿是人为编写的测试文字。它们用于验证协议、交互和生成行为，**不用于证明音频转写准确率、自然播客章节质量或时间对齐质量**。

真实模型样本为 12 句知识库学习文字，经真实 HTTP 领取、Bridge Codex app-server、心跳和完成回传，约 13.5 秒生成 5 章：资料收集与来源记录、搜索阅读与引用、复述与间隔复习、隐私与数据保护、知识库搭建要点回顾。模型只给句编号，返回时间由数据库原文计算。

首次调用因继承桌面启用 MCP 的配置，被既有安全检查拒绝。随后只给隔离子进程指定现有 Bridge 专用 Codex 运行环境，复验成功；没有关闭检查、复制凭据、重启共享 Bridge 或领取生产任务。

另一个样本含 660 句，两个批次由受控协议结果生成 42 章，用于验证 40＋2 分页、重试和跨页定位。这 42 章不是实际模型质量证据。

## 修复及保留的问题

联调中修复网页首次读取失败无直接重试入口、返回目录丢滚动位置，以及两端长目录翻页保留旧深层滚动位置的问题。鸿蒙密集文稿定位还需等布局稳定后执行；返回目录入口固定在滚动区外，避免用户从文稿深处反复滚回顶部。

首轮网页测试脚本曾把 Bridge 的 `jobId/lease.id/payload` 错写成其他字段，并在重试提交响应到达前领取；修正测试脚本后通过，错误日志保留。首次鸿蒙密集目录验证暴露滚动／返回问题，修复后重验，不将首次失败记成通过。

仍待验证：自然播客及小时级文稿的标题质量、跨批主题连贯性、四小时上限、真实手机布局和播放中断、生产 Bridge 与既有用户数据兼容。自动化测试数量不能替代这些验收。
