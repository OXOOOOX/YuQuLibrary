# P2 长节目检索问答本地验收

日期：2026-11-18。新增显式“检索整期文稿”，网页与鸿蒙可在独立阅读或音频已归档时按问题检索。问题、检索策略、转写任务、完整水位、源句映射及原文在提交时持久化；追问与重试沿用原证据。本文记录本地证据，生产服务、共享 Bridge 和华为后台本轮未变更。

## 行为与边界

- 原 `near/until/all/selection` 不改含义；旧 `all` 超出 600 段／32,000 字符仍拒绝。新检索入口不依赖播放位置，也不接管正在播放的另一集。
- `lexical-v1` 是有界中英文词法检索与评分，包含问题词覆盖和邻句窗口，没有向量索引。主命中与前后邻句一起占预算，以完整窗口去重；原文不裁剪，保留重叠／零时长时间戳。
- 源文稿上限 48,000 段／2,000,000 字符；问题最多 32 个检索词；最多 12 个主命中窗口，最后不超过 32 段／24,000 字符。它不是整期总结，普通“总结整期”不用于猜测全文观点。
- 没有合格证据时，业务服务直接保存明确提示，不发送模型任务、不提供原话题追问；可以调整问题重新检索。存在相关材料但缺关键事实时，由模型说明材料不足并引用实际材料。
- 追问只发送父问题 ID，扩展来源须显式重新检索；合法引用必须指向本轮冻结原文。编号合法不能代替语义核对。
- `yuqu.chat.retrieval.v1` 独立于旧 Bridge chat schema，领取前按能力过滤。新版页面声明 `anchored-v1,retrieval-v1`；旧端读取含检索消息的页收到升级提示。新能力离线仍可提交排队，无证据响应不依赖模型在线。

## 受控检索评测

固定样本在 `tests/fixtures/retrieval-corpus.mjs`，版本 `retrieval-controlled-v1`：720 段、51,216 个字符、合成一小时时间轴，超过两个旧上下文限制。这是人工构造文字，不是实际一小时音频或 ASR 准确率验证；UI 样本标为归档，没有用短音频伪装一小时时长。

先标注答案依据，再运行检索。12 道问题全部满足其标注条件，9 道有依据问题的 18 处必需原文全部保留，3 道无依据／通用问题返回空证据。覆盖开头和第 650／700 段附近、跨距约半小时的比较、块边界条件、缓存否定、重复陈述后的纠正、英文词形、被否决的预算数字和 C#／C++ 区分。这个受控结果不能推导自然播客召回率或误报率。

评测发现并修复：按单句去重会丢掉后文纠正；先选命中再补邻句会在 32 段上限截掉否定；符号丢失会混淆 C++／C#；中文单字碎片与通用提问会产生无关命中。回归另外检查完整窗口的字符上限、源顺序与原文不变、零时长以及查询／源大小拒绝。

本机纯内存成本样本为 48,000 段／1,908,880 字符，三次约 808／775／744 ms。检索是同步 JS 且处于数据库用户／对话锁事务内；SQL `statement_timeout` 不能限制该 CPU 阶段。这个单机成本测量不是并发服务延迟验收，后续若出现请求拥堵需评估异步执行与索引。

## 真实模型与数据库

隔离 Bridge 使用本地测试 API 和专用测试账号，未重启共享生产实例。两次均核对领取任务 ID 等于本次提交 ID，完整水位 3,600,000 ms、720 段、转写任务一致。

| 问题 | 实际结果及原文核对 |
| --- | --- |
| 路由器重连与离线日志清除分别需要什么条件 | 约 17.9 秒；指数退避 1／2／4 秒、最长 30 秒及随机抖动；离线日志上传并获服务端确认后才清除。引用 `[S2–S3]`、`[S5–S6]` 均支持所述事实 |
| 灯塔设备预算与交通费用总额是多少 | 约 8.3 秒；设备 8 万元、交通另计但无金额，因此总额无法确定；排除被否决的 10 万旧方案。引用 `[S5]`，未编造总额 |

`npm run test:integration` 在独立 `_test` 数据库全量 62 项通过；P2 六组进一步独立复核通过。覆盖旧 all 超限／新检索可用、预检查无写、幂等与复用冲突、账号隔离、未完成／水位不足拒绝、能力协商、无证据不派任务、源文稿改变后追问／重试仍冻结、旧租约拒绝、引用与收藏、归档以及整期删除清理。测试结束后才建立新的 UI 测试账号与资料。

## 网页与鸿蒙

网页环境为 `http://127.0.0.1:3000`，Chromium，1440×1080 和 390×844。Browser plugin not available，使用已安装 Playwright，脚本和截图保存在仓库外。流程：资料库 → 归档文稿 → 对话 → 整期检索／引用／追问。

| 网页检查 | 结果 |
| --- | --- |
| 页面身份、非空、框架错误层 | 通过；鱼趣页面与实际模型检索记录可读 |
| 引用与归档 | 原文展开、回答收藏通过，归档回听禁用 |
| 丢响应 | 注入 POST 已提交但响应丢失，重发 requestId 相同；无证据不成为父话题，继续保持检索锚点 |
| 原话题与新检索 | 追问只发送 parentTurnId，显式新检索只发送 retrieval anchor；验证排队后取消 |
| 手机布局及播放 | 无横向溢出；阅读／提问不改播放媒体、代次、位置 |
| 控制台 | 无未处理应用异常；一条 ERR_FAILED 来自故意注入的响应丢失 |
