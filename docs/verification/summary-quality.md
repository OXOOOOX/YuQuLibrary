## 已实施调整

- 旧版只按 600 句／24,000 字符预算分批，长教程的首批覆盖约 57:41，仅能输出最多六点。新增约 10 分钟时间跨度软边界，实际变为 7 段＋1 个整期归并；每条原句完整分配一次，字符上限和最多 128 批等原有约束保持。单句超过 10 分钟不拆造，零时长和重叠保留。
- 分段及整期提示词要求每点保持紧凑，所有事实、数字、条件和否定均由该点的 1–2 条引用直接支持；不足时缩窄内容，不靠其他未引片段或常识补全。随后针对审计发现明确后文补充、新示例或不同适用条件不等于推翻前文，只有材料明确否定或修改结论才称纠正。额外“覆盖更多主题”的提示实验没有验证出收益，未保留。编号和原句匹配仍不能自动证明语义支持。
- 策略升级为 `time-bounded-summary-v2`。两端旧结果提供“重新整理总结”，显式创建新版文档，保留旧输入、结果和冻结依据；新文档清空旧分页／依据并拒绝迟到响应。成功生成后使用新的请求标识，丢失响应时仍用原标识重试。没有新增迁移，也没有改写 `0014`。

三份样本旧版共 5 个、当前版共 10 个真实模型任务均完成。全部 90 个输出要点的引用通过 API 读取，并逐条对照生成时原文的编号、文字和起止时间一致。长教程本次累计任务耗时从 80.5 秒变为 134.8 秒，任务数从 3 变为 8；这是单次本机观测，不能当作稳定延迟或成本指标。

## 内容复核结果

内容审计明细保留在外部证据目录的 `tutorial-gold.json`、`baseline-audit.json`、`refined-audit.json` 和 `short-samples-audit.json`。长教程前后对照与短样本问题分开记录，不能把所有引用均存在等同于所有语义均正确。

长教程的第二轮 48 点中，39 点由自身引用完整支持，2 点需相邻原文补足，7 点存在专名／命令的 ASR 词面歧义；旧版 18 点分别为 1、13、4。没有发现完全无文稿来源的主张，但点的粒度和数量已变化，不能换算成通用准确率。整期六点对固定 12 主题的完整／部分／缺失从旧版 4／6／2 变为 1／6／5，说明证据绑定改善的同时出现覆盖退步：课程先决知识、配置／敏感信息／存储、Portainer 和结尾限制缺失。因此没有把第二轮定为质量通过。

第二轮两个短样本的 12 点中，9 点核心陈述由本点引用直接支持，另 3 点有问题：

- TWiT 第 1 点只引 S7–S8，“AI 将立刻改变一切”的前半句在 S6；事实有来源，但本点引用不全。
- Python 第 2 点的“括号内的引号”结构在 S20，当前 S21、S23 只直接说明引号内容和英文格式，存在小范围漏引。
- Python 第 4 点把后文补充写成“补充纠正”，原文并未说开头的单引号示范错误；“示例中含单引号”也在未引的 S33，本点 S43 仅陈述一般条件。应保留补充关系及条件，而非推定前文被推翻。本轮保留原始生成结果，没有手改成正确答案后再计通过。

据此试加选点规则，并补充上述补充／纠正约束，以**同一冻结输入**再调用实际 Bridge adapter 与 Codex：长教程仅重新归并已有 42 个子要点，两个短样本各重跑一段，共 3 次。输出继续通过 Bridge 解析及 domain 原句还原校验；这是隔离的生成复验，不领取业务队列、不改写既有数据库结果，也未重复客户端全链路。结果为 `*-focused.json`，审计为 `focused-audit.json` 与 `short-focused-audit.json`。

长教程选点实验的 12 主题为完整 1／部分 5／缺失 6，六点自身证据支持 4、相邻原文补足 1、ASR 专名歧义 1。虽补回课程先决知识和部分时长限制，架构、配置／敏感信息／存储、kubectl 操作和 Portainer 等仍遗漏，且部分其他主题掉出概览。故没有保留这条覆盖措辞，也没有把实验结果替换为业务数据库中的总结。下一步须评估六点概览的内容结构和主题预算，不能仅以增加提示词宣布问题解决。

最终短样本 12 点中 11 点由各自引用直接支持。Python 六点均支持：引号示例现在引用 S31、S33，限定“示例中的引号用法”，原文明示该示例代码无效，未再推定开头教学错误。TWiT 第 2 点仍漏引 S6，保留为未通过项；未用这组小样本建立准确率指标。

最终保留的分段提示词与这次短样本复验一致；整期提示词保留证据及补充／纠正约束，撤回覆盖实验措辞，未再重跑整期业务队列。客户端和数据库链路沿用前述完整验证，整期语义质量不计通过。

## 实际音频与客户端

Browser 插件未提供，网页使用已安装 Playwright 驱动实际 Chromium；不是模拟 audio API。先暂停 Python 在 30.502 秒，独立阅读 TWiT 总结并展开依据，播放媒体、代次和位置不变。显式回听 54.280–59.640 秒原文后，HTMLAudioElement 切换到 TWiT，实际时间从 54.300 推进到 55.297 秒，在 59.772 秒暂停；点击返回后恢复 Python 的 30.502 秒和暂停状态。390px 宽度无横向溢出、无页面异常，截图已查看。

另以受控的旧／新总结 HTTP 响应验证“重新整理总结”：新 documentId 被接纳，已显示旧依据清除，延迟旧依据响应不会混入新版，按钮和 busy 状态恢复。这项是浏览器响应注入；真实数据库升级幂等和旧记录保留另由集成测试验证。

最终 Debug HAP 安装到 HarmonyOS 模拟器，使用本地测试邮箱与实际私有音频接口。独立阅读同一 TWiT 总结不改变原 Python 位置；点击 46.280–54.280 秒的依据后，原生播放器出现 playing 事件、位置前进，54.325 秒暂停，返回后恢复 Python 30.502 秒及暂停状态。记录同时保留界面树、播放器事件和云端快照，不以接管 API 成功替代实际起播。截图已查看。未执行真机锁屏、耳机、来电或网络切换。
